# 당첨 화면 v5 — 앱 적용 명세

원본: `swc2026_WIN_PRIZE_iPad_template_v5_260923.aep` / 컴포지션 `15_WIN_PRIZE_IPAD_MASTER_V5` (2048×2732, 30fps, 30초).

## 방식: 상품별 AE 사전 렌더링 (2026-09-27 사용자 결정)

상품 PNG(`REPLACE TRANSPARENT PRODUCT PNG`, 2000² 안에 자동 맞춤)와 상품명(`EDIT_02_PRIZE_NAME`) 위로 WIN 글자·노이즈 광선·엠블럼·하단 패널이 계속 움직여, 앱에서 상품만 얹으면 겹침 순서가 달라진다. 그래서 상품마다 AE에서 영상을 뽑는다. 현장 변수와 기기 부하가 가장 적은 방식이다.

- 현재: 제라투 피규어(`win-prize-v5-2048x2732-master.mp4`)를 1024×1366 H.264 High 4.1, CRF 18로 인코딩한 `app/assets/oap/win/win-zeratu-figure.mp4`(30초, 12.5MB, 마스터 대비 52.4dB). 원본 마스터는 레벨 6.0이라 iPad Pro 3세대 한도(4.2)를 넘는다.
- 상품 확정 후: AE 사본에서 두 교체 자리를 바꿔 상품별로 렌더 → 같은 규격으로 인코딩 → 상품에 연결. 상품별 연결 방식(관리자 업로드 또는 앱 기본 자산)은 그때 정한다.

## 앱 동작 (swc-apac-v6)

- 당첨 경품(피규어 등급): 오픈 종료 → 흰 화면 → **상품 시네마틱 클립** 전체 화면 → 0.4초 페이드 → **v5 당첨 영상** 전체 화면(결과 진입과 동시에 첫 프레임부터).
  - 시네마틱: 관리자에서 그 상품에 등록한 `상품 영상`(videoKey)을 우선 쓰고, 없으면 번들 `assets/figure/zeratu-summon.mp4`(= `resource/videos/final-assets/zeratu-summon.mp4`). 재생 중에는 처음으로 돌아가기가 막힌다(기존 규칙).
  - 소리: 번들 클립은 기존 Web Audio WAV, 등록 클립은 영상 자체 소리. iPad가 소리 재생을 거부하면 무음으로 재생해 클립을 건너뛰지 않는다.
  - v5 영상 위 보라색 번개·색종이·흔들림은 쓰지 않고 팡파르만 남긴다.
- 스태프 확인: 오른쪽 아래 `SHOW THIS SCREEN TO STAFF / No. 일련번호 · 시각`, 2.4초에 등장.
- 복귀 (v7, 사용자 요청): v5 등장 애니메이션이 끝나는 2.5초(AE 마지막 등장 키: 하단 frame 불투명도 2.50초, 영상 시계 기준)부터 화면을 누르면 즉시 메인. 아무 동작이 없으면 7초 후 메인(동작이 있으면 그 시점부터 다시 7초). 참가상은 기존 5초. 떠날 때 v5 영상을 정지·되감고, 등록 클립을 썼다면 번들 클립 소스로 되돌린다.
- 참가상(미당첨): 기존 결과 카드 화면 그대로.
- 재고·로그 저장은 그대로 영상 재생 전에 한 번에 확정한다.

### v5 → v6 수정

- v5에서는 결과 화면을 한 번 거친 뒤 다음 당첨부터 v5 영상이 비어 노란 화면만 보였다. 메인 복귀 시 기존 정리 코드가 결과 화면 안의 모든 `<video>` 소스를 지우면서 당첨 영상까지 지웠기 때문이다(배포 사이트에서 readyState 0·networkState 0으로 재현). 정리 대상에서 당첨 영상을 제외했다.
- v5에서 뺐던 시네마틱 단계를 사용자 요청으로 복원했다(상품 영상 → v5).
