# 당첨 화면 v5 — 앱 적용 명세

원본: `swc2026_WIN_PRIZE_iPad_template_v5_260923.aep` / 컴포지션 `15_WIN_PRIZE_IPAD_MASTER_V5` (2048×2732, 30fps, 30초).

## 방식: 상품별 AE 사전 렌더링 (2026-09-27 사용자 결정)

상품 PNG(`REPLACE TRANSPARENT PRODUCT PNG`, 2000² 안에 자동 맞춤)와 상품명(`EDIT_02_PRIZE_NAME`) 위로 WIN 글자·노이즈 광선·엠블럼·하단 패널이 계속 움직여, 앱에서 상품만 얹으면 겹침 순서가 달라진다. 그래서 상품마다 AE에서 영상을 뽑는다. 현장 변수와 기기 부하가 가장 적은 방식이다.

- 현재: 제라투 피규어(`win-prize-v5-2048x2732-master.mp4`)를 1024×1366 H.264 High 4.1, CRF 18로 인코딩한 `app/assets/oap/win/win-zeratu-figure.mp4`(30초, 12.5MB, 마스터 대비 52.4dB). 원본 마스터는 레벨 6.0이라 iPad Pro 3세대 한도(4.2)를 넘는다.
- 상품 확정 후: AE 사본에서 두 교체 자리를 바꿔 상품별로 렌더 → 같은 규격으로 인코딩 → 상품에 연결. 상품별 연결 방식(관리자 업로드 또는 앱 기본 자산)은 그때 정한다.

## 앱 동작 (swc-apac-v8)

상품별 영상은 관리자 IP·상품 탭에서 등록한다(2026-09-28 사용자 결정). 앱에 번들된 당첨 영상은 없다.

| 상품 종류 | 영상 칸 | 쓰임 |
| --- | --- | --- |
| 피규어(당첨 등급) | 특별 영상 (선택) | 당첨 시 가장 먼저 전체 화면 시네마틱. 소리는 업로드 영상의 오디오를 Web Audio로 디코딩해 재생(iPad 제스처 밖 재생 대비), 디코딩 실패 시 영상 자체 소리 |
| 피규어(당첨 등급) | 당첨 영상 (선택) | 이어서 전체 화면 당첨 화면(OAP v5 사전 렌더). 없으면 기존 금색 당첨 카드 |
| 참가상 | 상품 영상 | 결과 카드 안 반복 영상(기존) |
| 참가상 | 클릭 팝업 영상 | 결과 카드 이미지를 누르면 열리는 영상(닫기 버튼, 끝나면 닫힘)(기존) |

- 흐름: 오픈 종료 → 흰 화면 → (특별 영상) → 0.4초 페이드 → (당첨 영상 또는 당첨 카드). 영상은 추첨 확정 즉시 IndexedDB에서 읽기 시작하고, 드래그 완료처럼 여유가 없으면 첫 영상이 준비될 때까지 흰 화면을 유지한다(최대 2.5초).
- 등록 규격: 특별·당첨 영상은 iPad Pro 3세대 H.264 한도(레벨 4.2, 프레임당 8704 매크로블록) 안이어야 등록된다. 2048×2732 마스터는 거부. 1024×1366 권장. 제라투 업로드용 파일: `resource/oap/upload-ready/zeratu-figure/` (special-video_zeratu-summon.mp4, win-video_zeratu-figure.mp4).
- 이전 데이터: v6까지 당첨 상품의 `상품 영상`을 시네마틱으로 썼으므로, 로드 시 당첨 상품의 `상품 영상`을 `특별 영상`으로 옮긴다.
- 백업: `.kuji` 백업·복원과 영상 제외 복원이 `specialVideoKey`, `winVideoKey`를 보존한다.
- 스태프 확인: 당첨 영상 오른쪽 아래 `SHOW THIS SCREEN TO STAFF / No. 일련번호 · 시각`, 2.4초에 등장.
- 복귀: 관리자 기본 설정 `결과 복귀(초)`(기존 비활성 `뽑기복귀` 칸 재사용, 최소 3초, 기본 7초)가 당첨 영상·당첨 카드·참가상 결과 모두에 적용. 당첨 영상은 등장 애니메이션 종료(2.5초, 영상 시계) 후 탭하면 즉시 메인.
